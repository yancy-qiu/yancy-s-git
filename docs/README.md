# 文档目录约定

`docs/` 用于存放“轻记 APP”的项目文档，避免产品判断、设计方案和开发实现混在一起。

## 目录结构

- `project-plan.md`：项目总规划，定义目标、范围、阶段和验收标准。
- `project-management.md`：项目状态台账，记录当前阶段、文档状态、变更和下一步。
- `product/`：后续存放 PRD、用户流程、信息架构等产品文档。
- `design/`：后续存放设计原则、组件规范、交互说明等设计文档。
- `development/`：后续存放技术方案、数据结构、测试与发布说明。
- `decisions/`：后续存放重要决策记录，文件名使用 `YYYY-MM-DD-主题.md`。

## 命名规则

- 文件和目录统一使用小写英文与连字符，如 `task-detail.md`。
- 文档标题使用中文，便于产品与设计阅读。
- 文档顶部必须写明状态、版本和更新时间。
- 未确认内容统一标记为“待确认”，不把假设写成定论。

## 维护规则

- 项目范围发生变化时，先更新 `project-plan.md`，再调整设计或代码。
- 每次实质更新同步维护 `project-management.md`，验证通过后创建本地 Git 提交。
- 推送到远程仓库前必须获得项目负责人明确授权。
- 已被新方案替代的内容保留决策记录，不直接删除历史原因。
- `sources/` 是同步参考资料，只读，不在本目录复制或修改。
