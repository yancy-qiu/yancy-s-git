## 执行方式

在仓库 `web/` 中使用 Node.js 22+，依次运行：

```bash
npm ci
npm test
npm run build
npm run test:e2e
```

端到端测试默认使用 `/usr/bin/chromium`，其他机器通过 `CHROMIUM_PATH` 指定 Chromium。Playwright 自动启动 5174 端口的测试服务；生产 Supabase 变量由虚拟测试配置覆盖，网络请求由测试拦截，不访问真实账号或真实模型。失败截图与上下文保存在 `/tmp/qingji-playwright-results`。没有跳过、禁用用例或预期失败用例。

## 本次修复

1. 空白标题校验原来在错误处理之前抛出，界面没有提示；改为显示字段校验消息。
2. preferences 为 null 或演示缓存为错误结构时可能使页面崩溃；现在验证读取结果，损坏的演示缓存停止写入并保留原数据。
3. 演示退出不触发用户 ID 变化，导致旧对话残留；现在显式清除工作区临时状态。
4. AI 请求结束晚于退出时，错误分支可能回填上一会话输入；增加会话版本检查，旧请求不更新新会话。

## 测试运行诊断

读取 503 的测试最初等待 5 秒，但 Supabase SDK 默认在 1、2、4 秒后重试。检查 SDK 实现后将断言窗口改为 15 秒，并验证实际发生至少四次请求；没有禁用生产重试，也没有移除失败断言。此问题属于测试等待时间设置，不是未解决的严重应用故障。

已复现的应用缺陷均在首轮代码修复后通过对应回归。遵守每个严重问题最多三轮修复的限制；没有需要继续第四轮修复的严重问题。
