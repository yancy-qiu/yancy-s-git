## 用户流程

顶部“新建会议纪要”打开宽版编辑界面；保存后与任务共同出现在统一列表，显示会议纪要标识。点击纪要进入宽版阅读，点击“编辑纪要”进入编辑。侧栏可按会议纪要能力筛选。显示名称与文档能力分开：修改任务类型名称不会改变文档类型。

支持 H1–H3、粗体、斜体、下划线、编号/无序/勾选列表、引用、链接、撤销重做及 Tiptap 默认 Markdown 输入规则。可在空白正文中使用包含主题、时间与参会人、讨论要点、结论、行动项的模板，已有正文不因点击模板被覆盖。正文支持最多 100000 字符，结构化文档上限 500000 UTF-8 字节。

AI 整理使用现有模型配置，只向用户所配服务发送纪要原文。结果先预览，用户采用后才替换编辑内容，仍需明确保存；取消或请求失败保留原文。整理期间正文发生变化则拒绝采用旧结果，不自动新建行动项任务。普通任务 AI 修改纪要时允许修改安排等元数据，正文保持原结构化内容，正文整理使用专用入口。

## 数据与保存

`tasks.record_kind` 为 task / meeting_minutes，默认 task；`document` 保存结构化 Tiptap JSON，`content` 保存用于搜索与 AI 的纯文本。现有行保持普通任务。会议纪要当前以 meeting 分类为默认关联，不依赖分类名称识别。

显式保存沿用原有账号隔离、时间戳并发检测及失败保留行为。新列未迁移时，普通任务写入不提交新增列；纪要保存失败会保留编辑状态与本机草稿，不能声明已保存。

草稿按账号和记录 ID 分开，本机新增纪要使用一个新建草稿槽。400ms 防抖暂存，关闭前补存；恢复/移除由用户明确选择。已损坏草稿停止覆盖；其他页面更新相同草稿后本页停止自动覆盖，提示先保存当前内容。保存成功仅删除本页识别的草稿版本，不删除其他页面的新版本。草稿未跨设备同步，浏览器清理站点数据会移除草稿；账号切换不会将上一账号草稿载入新账号。

## 实现文件

- `web/src/MinutesEditor.vue`：按需加载的宽版编辑/阅读、工具栏、模板、草稿与预览。
- `web/src/minutesDocument.ts`：文档格式校验、纯文本提取和模板；拒绝不支持节点、层级过深及脚本链接。
- `web/src/minutes.ts`：专用 AI 整理请求，返回结构化文档并校验。
- `supabase/migrations/202611100003_meeting_minutes.sql`：新列、文档约束与长文本限制。

不使用 v-html 展示模型返回内容；通过限定的 Tiptap 节点/标记和 JSON 校验呈现。仅允许 http/https/mailto 链接，不支持图片、附件、代码块、表格或多人实时编辑。

## 上线步骤与当前阻塞

执行第三份迁移前，应检查 task_categories、tasks 表及当前列状态，确认前两份迁移已完成。本迁移是一次性事务，不能盲目重复运行。先在目标数据库核验，再执行，最后检查新列、约束、既有任务数量、按账号的读取/写入权限和真实纪要保存。

本对话当前环境仍报告无 Supabase 管理密钥，`api.supabase.com` 探测返回代理 CONNECT 403。因此未执行第三份线上迁移，未发布本轮功能；不要求用户重新生成或在聊天中粘贴密钥。需要将已有配置实际应用到执行环境后，由助手继续迁移。
