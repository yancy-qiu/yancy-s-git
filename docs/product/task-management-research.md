# 任务管理方法与专用 AI 调研

> 状态：调研建议，产品取舍待确认；未接入运行时
>
> 版本：V0.1
>
> 更新时间：2026-11-10

## 结论

建议先做「轻量 GTD + 下一步行动 + 每日容量规划 + 周回顾」的任务管理 Skill，以现有模型作为执行引擎，明确规则作为校验层，数据库保存用户偏好。先把流程做专，再通过评测决定是否换小模型或微调。Skill 与小模型可以组合，二者并非替代关系。

这不是方法有效性的临床/实验性综述，也没有实测过候选小模型。下文区分通用方法分析、已读取的一手技术资料及待核验资料，不把厂商能力描述当作本产品效果保证。

## 1. 方法比较及产品取舍

| 方法 | 核心做法 | 对轻记的价值 | 局限与使用边界 | 建议 |
| --- | --- | --- | --- | --- |
| GTD | 收集、厘清、组织、回顾、执行；把模糊事项转成下一步行动 | 用户随手记录后，由助手整理可执行动作、等待事项和未来事项 | 完整 GTD 有维护负担，不要求用户先建立复杂清单；两分钟规则是行动建议，不自动替用户执行 | 作为整理主线，隐藏术语 |
| 艾森豪威尔矩阵 | 分开判断重要性与紧急性 | 解释「为什么先做这个」，防止所有任务都标高优先级 | 重要性需要目标背景；紧急性需要真实截止日期。当前 App 的安排日期不一定是截止日期，不能直接推导紧急性 | 作为判断原则，不急于增加四象限界面 |
| 时间块 Time blocking | 将任务放入实际可用时间段 | 把愿望清单变成可完成的日计划，识别容量超载 | 需要可用时段、时长、固定日程；没有日历权限时不能声称查过日历或无冲突 | 日规划建议，用户确认后才变更多项安排 |
| 个人看板 / WIP 限制 | 可视化待办、进行中、完成，限制同时开始的工作 | 减少反复切换，先推进一个明确行动 | 当前只有 completed，没有独立进行中/阻塞状态；不能把未完成都当正在做。个人 WIP 上限是适配建议，不是所有看板的固定规则 | 先在对话中建议少量进行中任务，不先做新看板 |
| 番茄工作法 | 专注一段时间后休息，观察实际投入 | 帮助启动拖延或大任务，提供轻量陪伴 | 25/5 是常见起点，不适用于所有工作；计时不能代替计划。App 目前没有计时器 | 可选专注建议，非核心排程依据 |
| SMART / 目标拆解 | 明确目标、成果标准和时间边界 | 把「做完项目」拆成能验收的小步 | 不能强迫每条琐事都填完整目标，也不能凭空补指标或承诺日期 | 用于复杂任务的完成标准 |
| 每日重点 + 周回顾 | 每天选少量重点，定期整理未完成、等待和失效任务 | 让用户知道现在做什么，以及任务是否仍值得做 | 「每天三件」是产品默认建议，不是科学最优值；不能把所有逾期任务自动推到明天 | 作为持续使用的核心闭环 |

建议用户看到的流程只有：**随手记 → 理清下一步 → 今天先做什么 → 做完回顾**。方法论在后台指导助手，不让用户学习一套术语。

## 2. 建议的四个能力

1. **整理记录**：区分可执行任务、会议、进展、需求；有充分信息即保存，不因为缺少日期而追问。
2. **拆解任务**：表达成「动词 + 对象 + 完成标准」，输出下一步与最多三条行动项；缺少会改变行动方向的信息时，只问最关键的问题。
3. **规划今天**：结合用户目标、硬截止、依赖和可用时间，提出少量重点及缓冲；容量未知先给排序建议，不伪造日程。
4. **每日/每周回顾**：询问未完成原因，区分保留、缩小、等待、改期、放弃；发现重复延期先处理阻塞，不自动不断顺延。

这些流程默认是建议。用户明确要求创建或修改单条任务时可按现有权限执行；批量重排、删除和多任务变更需要一个具体可审阅方案再确认。

## 3. Skill、规则和模型怎么分工

| 层 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| Skill | 何时整理/拆解/规划/复盘，提问策略、示例与表达方式 | 不保管 API Key，不自动赋予工具权限，不保证模型绝不犯错 |
| 规则与工具 | 字段合法性、任务归属、日期范围、容量计算、写入与撤销 | 不靠关键词猜测所有复杂用户意图 |
| 用户记忆 | 用户确认的工作时段、每日可用时间、重点目标、拆解粒度、偏好语言 | 不把个人偏好训练进共享模型；一次聊天不默认变永久偏好 |
| 通用/小模型 | 理解自然语言，运用流程形成建议和结构化输出 | 不作为数据库和长期记忆，不拥有最终校验权 |
| 检索（可选） | 按需取方法说明、项目资料或用户历史摘要 | 不是启动阶段必需的向量数据库工程 |

**Skill 不是训练一个模型。** 它是可版本化的工作流程包，能对接不同模型；微调则改变模型参数。只在仓库放一个 SKILL.md，不会让目前的 Vue App 自动识别它。

## 4. 与当前代码的真实差距

已检查 `web/src/ai.ts`、`domain.ts` 及现有 PRD：

- 现在是一个系统提示词，发送最近六条对话及一条引用任务；没有 Skill 加载器、完整任务列表上下文或长期用户偏好。
- 输出只有 create/update/none 和一条 task。拆解可先放 actionItems（最多三项），不能直接创建多层子任务或多条任务。
- 模型目前不能读取用户所有任务，因此不能可靠回答「我今天应该先做什么」，也不能声明已检查全局冲突。
- priority 只有 high/normal/low，重要性筛选复用 high；尚不能独立表达重要与紧急。
- due_date 是安排字段，不等同真实截止；尚无估时、依赖、等待/阻塞状态及日历空闲数据。
- 当前 AI 未暴露删除/批量写入工具。建议型规划先 action:none，不能在 reply 说「已全部改期」。

## 5. 推荐接入方案

第一步仅做可回退的单任务增强，建议文件位置（尚未实现）：

```text
web/src/ai/skills/
  task-management/SKILL.md
  task-management/examples.json
web/src/ai/
  context.ts       # 时区、所选任务、授权范围内的相关信息
  skill-loader.ts  # 显式加载当前流程与版本
  validator.ts    # 延用并扩充现有 Zod 校验
```

运行路径：识别整理/拆解/建议意图 → 加载 Skill → 加入最少必要上下文 → 调用用户已配置模型 → 校验结构和任务归属 → 单任务写入或展示建议。Skill 内容进入 system 提示；任务正文与检索资料始终是数据，不能覆盖系统约束。必须记录 Skill 版本以便复现，并提供切回现有提示词的开关。

第二步再增加「规划今天」「周回顾」：在登录鉴权范围内获取相关任务摘要，先给只读建议；引入容量、硬截止等必要字段后，再做可确认的批量操作。多任务协议与事务/部分失败处理单独设计，不把批量操作塞进当前单任务 schema。

用户记忆建议在已鉴权的用户偏好表按账号隔离，允许查看、修改、忘记；演示模式使用本机独立偏好。具体字段、云端保存与默认行为均待确认，本轮不新增表。

已提供一个兼容现有单任务协议的文档草案：`docs/development/task-management-skill/SKILL.md`，以及评测场景。该草案不代表 App 已支持自动加载 Skill。

## 6. 小模型路线

可以做，但建议先**评测现成小模型**，再决定是否微调，而不是从零训练。

- 候选示例：Qwen3 官方仓库列出了 0.6B、1.7B、4B 等规模；其中 Qwen3-4B-Instruct-2507 可作为中文任务场景的候选基线之一。这不是最新模型排行榜，也不表示已经验证它优于用户当前模型。
- 简单意图识别、分类、日期/字段提取适合优先测试小模型；复杂澄清、多任务冲突和规划，需要更完整上下文与更严格评测，可保留较强模型回退。
- 先让相同 Skill 分别运行在现有模型和候选小模型上，比较质量、费用与真实端到端耗时。小参数不自动意味着整体延迟更低，部署和网络同样影响结果。
- 若固定格式、分类口径等反复失败，且高质量数据足够，再考虑 SFT + LoRA/PEFT。训练数据应为用户授权、去标识的输入/期望输出与人工纠错，排除密钥及无授权私人任务。
- 不用模型权重保存每个人的日程。个体事实保存在数据库，运行时提供必要上下文。
- 本地推理需要部署服务、适当硬件和接口适配；当前 App 仅接受 HTTPS OpenAI 兼容地址，不能声称直接填 localhost 的 HTTP 地址就能用。精确内存、吞吐、许可证和部署方式须针对选定模型版本实测/核验。

是否微调应由保留测试集上的实际收益决定，不设「收集到 N 条就一定能训练好」的承诺。若换小模型导致澄清、日期或越权问题增多，即使便宜也不采用。

## 7. 验证方式与建议门槛（待确认）

先冻结现有提示词基线，使用相同任务、日期时区和上下文比较：现有提示词、Skill + 同一模型、Skill + 候选小模型。把示例与保留测试集分开，固定模型版本与采样参数；重复运行观察波动。记录 p50/p95 端到端耗时、费用、写入成功率、日期准确率、关键意图正确率和不必要追问率。

第一批场景已写在 `references/evaluation.md`。建议扩展到 50–100 条经过人工审核的中文样例，覆盖模糊表达与反例，而不是复制同一提示的改写。真实用户试用应先获得授权。

发布条件建议：

- 保留集中的越权修改、伪造完成和未经同意的批量变更为 0；有限测试为 0 不代表生产风险为 0。
- 指定日期/时区、明确优先级、引用任务身份等关键字段全部通过确定性场景。
- 任务有足够信息时直接完成，缺少日期不作为必问项；未知信息留空而非编造。
- 两位评审（资源允许时）盲评下一步是否可执行、建议是否符合容量、是否徒增维护成本。
- 小模型未达到质量基线时回退，不用成本下降掩盖错误增加。

## 8. 推荐先做什么

**先接入「轻记任务教练 Skill V0.1」：整理、拆解和下一步行动；继续沿用用户当前模型。** 验证有效后补每日规划和用户偏好，再独立评测小模型。首版不新增复杂方法论设置页、不训练模型、不声称完整 GTD/日历自动规划。

以上是建议，方法组合、自动写入边界、记忆字段和模型部署方式待用户确认。本次仅调研与草案，不改变产品范围或发布功能。
