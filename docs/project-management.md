| `feat` | 新增用户可见功能 | `feat: add quick task creation` |
| `fix` | 修复错误 | `fix: preserve task date after edit` |
| `refactor` | 不改变功能的代码整理 | `refactor: simplify task storage` |
| `test` | 新增或修改测试 | `test: cover overdue task rules` |
| `chore` | 工具、配置或维护工作 | `chore: add local development script` |

一次提交只包含一个清晰目的。未完成、未验证或混有无关改动的内容不提交。

### 7.3 远程同步边界

- 线上准本：GitHub 远程仓库 `git@github.com:yancy-qiu/yancy-s-git.git`。
- 开始修改前：先检查远程分支是否有其他位置提交的新内容。
- 本地提交：每次完成实质更新后自动执行。
- 远程推送：每次都需要 Yancy 明确授权。
- 远程已变化时：先安全合并，不覆盖其他位置的修改。
- `rebase`、`reset --hard`、强制推送和删除 Git 历史：必须先获得明确授权。
- 当前远程状态：已连接，`main` 分支已建立并完成首次同步。
